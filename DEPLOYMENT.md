# FINN — Gemini release guard + deployment/submission kit

**This is a small patch, not another FINN rewrite.** It replaces only `backend/app/research_ai.py`, preserving its public functions (`ModelUnavailable`, `configured`, `generate_json`, `context_block`, `synthesise`). It adds tests, a live Infosys smoke script, and stand-alone GitHub/deployment helpers. **It does not change** your database, improved PDF extraction, retrieval ranking, portfolio, daily briefing, alerts, React UI, or guidance comparison endpoint.

## 1. Install source-only Gemini guard

Stop the existing backend. Unzip the kit, open PowerShell in `finn-gemini-release`, and run:

```powershell
python apply_release.py --backend "C:\path\to\your\FINN\backend"
cd "C:\path\to\your\FINN\backend"
.\.venv\Scripts\Activate.ps1
python -m pytest -q
```

The installer requires the known Phase 4 `research_ai.py` API and Gemini provider. It backs up the original AI module under `backend/release-backups/`, then copies **only** the replacement AI module and two new test scripts. It stops if an existing test file differs. No reindex is required because the PDF cache and retrieval implementation are unchanged.

The guard asks Gemini for up to three **verbatim quotes**, not free-form financial summaries. The server checks source ID, exact quote substring and basic topic overlap, then constructs the visible answer entirely from those verified quotes with `[S#]` citations. If support is missing, it abstains. Numbers are not generated by the model in the final answer. This is intentionally conservative and does not prove that a quote alone answers a complex research question; users must still inspect the original source.

## 2. Set your Gemini key safely — backend only

Obtain a key from https://aistudio.google.com/apikey . In the backend PowerShell terminal:

```powershell
$secure = Read-Host "Enter Gemini API key (hidden)" -AsSecureString
$env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new("", $secure).Password
$env:FINN_GEMINI_MODEL = "gemini-3.5-flash-lite"
$env:FINN_GEMINI_MAX_CALLS_PER_PROCESS = "60"
```

Do not print the key, send it in chat, put it in `.jsx`, check it into GitHub, or add `VITE_` prefix. Set it as a secret environment variable on the backend host during deployment. Gemini's limits and model access depend on your AI Studio project; if this model is unavailable, set `FINN_GEMINI_MODEL` to another **model ID listed as available in your account**. Existing `gemini-2.5-flash` access may be restricted for newer projects. Do not repeatedly retry an HTTP 429 error.

The in-process 60-call guard is a basic **single-worker** cost fuse, not global rate-limiting or authentication. Before allowing strangers to use a public hosted prototype, control access/quotas and watch Google AI Studio usage. Free-tier prompts may be used to improve Google's products; review the applicable data terms before sending any sensitive documents. FINN sends only source excerpts, not the entire PDF database.

## 3. Test real Infosys questions, including a negative case

Your local reindexed Infosys documents must already exist in the backend SQLite database. Keep the Gemini key configured in the **same terminal** as this command:

```powershell
python -m scripts.test_infosys_gemini
```

The live test asks three questions:

1. **Business risk:** `What business risks and cybersecurity exposures does Infosys describe?`
2. **Risk management:** `What risk management and information security controls are described?`
3. **Unsupported negative:** `What was Infosys profit from the Neptune spacecraft project in FY2042?`

For the first two, expect `status=answered`, original source citations, and quotes that exist on the cited PDF pages. If the real documents do not directly support the question, a safe abstention is expected; **the script does not count that as a passed positive-case demo**. For the negative, expect `status=insufficient_evidence` and no invented profit figure. The script exits with an error if this gate does not pass. Do not report a passing *live* test until it succeeds on your own indexed Infosys documents and Gemini account.

If Gemini is inaccessible, the existing `/api/research/ask` endpoint returns `model_error` with source passages, not invented figures. Guidance-vs-actual comparison retains its prior strict period/quote checks. It can correctly respond `insufficient_evidence` for FY2027 before full-year results exist.

**Offline validation:** `python -m pytest -q tests/test_gemini_release.py` verifies quote integrity, numeric hallucination rejection, invalid IDs, abstention, and secure header configuration. These tests are mocked and do not substitute for live testing.

The release builder copies code and documentation, **never** `.venv`, `node_modules`, local SQLite files, `.env`, keys, cached downloads, or backups. It also scans source for likely hardcoded Gemini API keys and aborts if found. Review `git status` before committing. The generated repository has `backend/`, `frontend/`, `render.yaml`, `.gitignore`, and `DEPLOYMENT.md`.

Create a repository through https://github.com/new , then (replacing your account/repo):

```powershell

```

Start private while checking for sensitive material; change visibility to public only when reviewed, or grant evaluators access. Do not commit your production SQLite database or the Gemini API key.

## 5. Deploy backend to Render **with persistent SQLite**

Render's *Free* web-service filesystem is ephemeral and cannot attach a persistent disk. **Do not deploy your only working SQLite copy there.** The provided `render.yaml` configures a **paid Starter** web service with a persistent disk at `/var/data` and `FINN_DB_PATH=/var/data/finn.sqlite3`. This preserves SQLite across restarts/redeploys. Hosting costs apply. Reference: https://render.com/docs/disks and https://render.com/docs/free .

1. In Render, connect the GitHub repository and create a **Blueprint** using the root `render.yaml`, or manually create a Python web service with root `backend`.
2. Confirm build command `pip install -r requirements.txt`, start command `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, health path `/health`.
3. In Render dashboard **Secrets / Environment**, set `GEMINI_API_KEY` (hidden). The Blueprint already defines `FINN_GEMINI_MODEL` and the SQLite path. Use one backend worker for this SQLite prototype.
4. Wait for the backend service to start and note its real HTTPS origin (e.g. `https://finn-fastapi.onrender.com`).
5. Upload a consistent snapshot of the **existing populated local SQLite** into the persistent disk, separately from GitHub, as follows:

In your own machine, from the extracted kit directory (not the Git repo):

```powershell
python deploy/backup_sqlite.py `
  --source "C:\path\to\FINN\backend\data\finn.sqlite3" `
  --output "C:\FINN-private\finn-upload.sqlite3"
```

The script uses SQLite's online backup API and checks integrity. Then use **Render's documented SCP/SFTP transfer** after configuring service SSH (https://render.com/docs/disks and https://render.com/docs/ssh):

```powershell
# Replace the example Render SSH endpoint shown in your service's Connect > SSH tab.
scp -s "C:\FINN-private\finn-upload.sqlite3" YOUR_SERVICE@ssh.YOUR_REGION.render.com:/var/data/finn.incoming.sqlite3
```

In the Render service **Shell**, check the uploaded DB with `python -c "import sqlite3; c=sqlite3.connect('/var/data/finn.incoming.sqlite3'); print(c.execute('PRAGMA integrity_check').fetchone()[0])"` and only then replace `/var/data/finn.sqlite3` during a maintenance/idle window. Restart the service so all connections use the uploaded DB. Keep the original local DB as a backup. If your host uses a different paid/SSH workflow, follow the host's official instructions rather than exposing an unauthenticated file-upload API.

After service restart, verify:

```text
https://YOUR_REAL_BACKEND.onrender.com/health
https://YOUR_REAL_BACKEND.onrender.com/api/portfolio
https://YOUR_REAL_BACKEND.onrender.com/api/briefing?hours=168
https://YOUR_REAL_BACKEND.onrender.com/api/research/INFY/documents
```

**The `/health` endpoint only proves process health.** Inspect actual record counts, original filing links and indexed Infosys documents before calling deployment successful. You may need to refresh the NSE catalog and documents if the snapshot lacked them.

## Known honest limitations

- Source quotation validation prevents invented numbers from being returned as verified direct quotes; it **does not prove** that a selected quote is fully responsive, nor that all financial information was extracted from tables.
- The Gemini model, paid hosting, data-source access and public-company PDF links must be validated in your own accounts. No external deployment or live Gemini call was executed in this kit's build environment.
- This prototype has no authentication. The per-process call fuse and Google AI Studio rate limits are not substitutes for production API authentication and abuse protection. If publicly accessible, monitor usage closely, set quotas/billing safeguards, and avoid uncontrolled document ingestion.
- The private SQLite upload should follow applicable source licenses/data redistribution rules. Do not publish extracted filings, portfolio holdings, or confidential data without permission.
